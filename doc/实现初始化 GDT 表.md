### GDT表

```
临时 GDT（Bootloader 阶段）:
  [0] Null 描述符（必须的空条目）
  [1] 代码段：基址=0, 界限=4GB, 可读可执行
  [2] 数据段：基址=0, 界限=4GB, 可读可写
```

#### 当前内核需要的段描述符

```
GDT 布局（最小可用）:
┌─────────────────────────────────────────────┐
│ [0] Null 描述符 (全零，CPU 强制要求)          	│  偏移 0x00
├─────────────────────────────────────────────┤
│ [1] Kernel Code Segment (内核代码段)          │  偏移 0x08
│     Base=0, Limit=4GB, Ring 0, 可执行可读     │
├─────────────────────────────────────────────┤
│ [2] Kernel Data Segment (内核数据段)          │  偏移 0x10
│     Base=0, Limit=4GB, Ring 0, 可读写        │
└─────────────────────────────────────────────┘
```

### 配置 GDT 表的完整步骤

```
1. 在 C 代码中定义 GDT 表（结构体数组）
2. 填充 Null + Code + Data 三个描述符
3. 准备 GDTR 结构（记录 GDT 的地址和大小）
4. 用汇编指令 lgdt 加载 GDTR
5. 用远跳转（far jump）刷新 CS 寄存器
6. 重新加载 DS/ES/FS/GS/SS 寄存器
```



### 配置完GDT 表能做什么

#### 1. 彻底掌管“内存控制权”（内核安全的起点）

在加载你的 GDT 之前，CPU 用的还是 Bootloader 留在内存里的那个“临时 GDT”。 Bootloader 占用的内存空间随时可能被你的内核覆盖，一旦覆盖，CPU 就会立马崩溃。

- **现在**：段寄存器（`CS`, `DS`, `SS` 等）指向的是你自己在 C 语言中定义的 `gdt` 数组。**CPU 明确知道自己处于 Ring 0（最高特权级），拥有对全 4GB 内存的绝对读写权限。**

#### 2. 解锁了“中断响应能力”（硬件要求的先决条件）

这是接下来最重要的一点：**没有正确的 GDT，CPU 绝对无法处理任何中断或异常。**

- 当键盘被按下、定时器滴答、或者发生“除以零”错误时，CPU 会去查 **IDT（中断描述符表）**。
- 但 IDT 中的每个中断处理入口，**都必须绑定一个 GDT 中的代码段选择子（CS Selector，即 `0x08`）**。
- **现在**：CPU 已经准备好了 `0x08` 这个绝对可靠的代码段。这意味着，**我们可以开始配置 IDT（中断）了！**

#### 3. 奠定了“多任务与用户态（Ring 0 → Ring 3）”的基础

将来你的 OS 要运行用户程序（比如一个 `main.c` 编译出来的普通应用），用户程序不能直接访问内核内存。

- **现在**：GDT 框架搭建好了。以后我们要支持用户态，只需要往这个 `gdt` 数组里追加两个条目：
  - `[3] User Code Segment`（DPL=3，Ring 3）
  - `[4] User Data Segment`（DPL=3，Ring 3）
  - `[5] TSS (Task State Segment)`（用于用户态切换回内核态时恢复栈）
    CPU 就能依靠 GDT 硬件级地阻止用户程序越界访问内核。
